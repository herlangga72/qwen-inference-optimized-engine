> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Take tokenization from 342k tokens/s (2.9 MB/s) to at least 10M tokens/s on this box while producing byte identical ids.

**Architecture:** Four units, each testable alone: a hand-written pre-tokenizer scanner for the `qwen35` and `qwen2` expressions (Task 3, scalar; Task 5, AVX2 ASCII fast path) replacing `std::regex`; merge ranks keyed by packed token ids (Task 2) replacing the string-pair hash map; a chunked threaded driver with a vocab-owned pool (Task 4); and a detokenize fast path (Task 6). **Tech Stack:** C++17, `src/llama-vocab.cpp`, `src/unicode.cpp` (codepoint tables), AVX2 intrinsics, CMake, `llama-tokenize`, `test-tokenizer-0`.

### Task 2: Merge ranks keyed by token ids

**Files:**
- Modify: `src/llama-vocab.cpp` (`bpe_ranks` at line 388, its construction around line 533, and the lookup in the merge loop)

**Interfaces:**
- Consumes: the vocab's `token_to_id` map, populated before merges are read.
- Produces: `llama_vocab::impl::bpe_rank(uint32_t left, uint32_t right)` returning the rank or `INT32_MAX`, backed by a flat table.

- [ ] **Step 1: Replace the map with a keyed table**

In the vocab's impl struct, replace:

```cpp
    std::unordered_map<std::pair<std::string, std::string>, int, pair_hash> bpe_ranks;
```

with:

```cpp
    // merge rank per (left, right) token id pair, packed into one key
    std::unordered_map<uint64_t, int32_t> bpe_ranks;
    // small per-left cache built lazily for the common case
    std::vector<std::vector<std::pair<uint32_t, int32_t>>> bpe_ranks_by_left;

    static uint64_t bpe_key(uint32_t left, uint32_t right) {
        return ((uint64_t) left << 32) | (uint64_t) right;
    }

    int32_t bpe_rank(uint32_t left, uint32_t right) const {
        const auto it = bpe_ranks.find(bpe_key(left, right));
        return it == bpe_ranks.end() ? INT32_MAX : it->second;
    }
```

- [ ] **Step 2: Build it from ids instead of strings**

At the construction site (line 533), map both halves of each merge through `token_to_id` once and insert the packed key. Merges whose halves are not in the vocabulary are skipped, exactly as the current code skips them:

```cpp
                    const auto it_l = token_to_id.find(first);
                    const auto it_r = token_to_id.find(second);
                    if (it_l != token_to_id.end() && it_r != token_to_id.end()) {
                        bpe_ranks.emplace(bpe_key(it_l->second, it_r->second), i);
                    }
```

- [ ] **Step 3: Use ids in the merge loop**

In the BPE session's merge loop, the candidate identity becomes two ids. Where the code currently builds `std::string` halves and looks them up, keep the symbol's cumulative token count and id on the linked-list node and look up:

```cpp
                const int32_t rank = vocab->bpe_rank(symbols[i].id, symbols[j].id);
```

Add an `uint32_t id` field to `llm_symbol` (initialised to `UINT32_MAX` for a byte-level symbol, and to the merged id when a merge is accepted), so no string is built per candidate. The `llm_bigram_bpe::text` member and its construction are removed with it.

- [ ] **Step 1: Implement the rule set**

The `qwen35` expression is an ordered alternation. Implement it in that order, at every position:

```cpp
// ordered alternatives, matching the qwen35 expression exactly
// 1. (?:'s|'t|'re|'ve|'m|'ll|'d)
// 2. [^\r\n\p{L}\p{N}]?[\p{L}\p{M}]+
// 3. \p{N}
// 4. " ?[^\s\p{L}\p{M}\p{N}]+[\r\n]*
// 5. \s*[\r\n]+
// 6. \s+(?!\S)
// 7. \s+
```

For each alternative write the scan as a small loop over codepoints:

- Alternative 1: a single quote followed by one of the listed contractions, case-insensitive on the letter, longest match first (`'re`, `'ve`, `'ll` before `'r`, `'v`, `'l`).
- Alternative 2: an optional leading codepoint that is neither `\r`, `\n`, letter nor number, then one or more of letter or accent mark.
- Alternative 3: exactly one number codepoint.
- Alternative 4: an optional ASCII space, then one or more codepoints that are not whitespace, letter, accent mark or number, then any run of `\r` and `\n`.
- Alternative 5: any run of whitespace, then at least one `\r` or `\n`.
- Alternative 6: a run of whitespace that is *not* followed by a non-whitespace codepoint, which is the `(?!\S)` lookahead, and which therefore only matches at the end of the text or before nothing at all.
- Alternative 7: any run of whitespace.

Emit the matched range as one word. If no alternative matches at a position, advance one codepoint and emit it as a single word, which is what the reference does with a no-match character.

- [ ] **Step 2: Expose the word iterator**

Provide `unicode_split_qwen(...)` as above, with the classification done through a helper that the next task will make SIMD:

```cpp
inline uint32_t classify_ascii(unsigned char c) {
    // bit 0 letter, bit 1 digit, bit 2 space, bit 3 other
    if (c >= 'A' && c <= 'Z') return 1u | (c <= 'Z' ? 0u : 0u);
    if (c >= 'a' && c <= 'z') return 1u;
    if (c >= '0' && c <= '9') return 2u;
    if (c == ' ' || c == '\t' || c == '\r' || c == '\n' || c == '\v' || c == '\f') return 4u;
    return 8u;
}
```

with non-ASCII falling through to `unicode_cpt_from_utf8` and the flag testing.

### Task 4: The chunked threaded driver

**Files:**
- Modify: `src/llama-vocab.cpp` (a new driver, and `llm_tokenizer_bpe::tokenize` calls it)

**Interfaces:**

- [ ] **Step 1: Define the safe split rule**

A position is safe if it is the start of a word that begins with whitespace, or the start of the text. Because the pre-tokenizer's alternatives 5 to 7 all begin at whitespace and consume it, splitting immediately before a whitespace run cannot change how either side tokenizes:

```cpp
// a split is allowed before a whitespace codepoint, because every whitespace-led
// alternative consumes the run from its start, and the BPE merges never cross words
static size_t find_split(const char * text, size_t len, size_t target) {
    for (size_t p = target; p < len; ++p) {
        const unsigned char c = (unsigned char) text[p];
        if (c == ' ' || c == '\t' || c == '\r' || c == '\n' || c == '\v' || c == '\f') {
            return p;
        }
    }
    return SIZE_MAX;
}
```

The boundary test in Step 3 verifies the rule empirically rather than trusting the argument.

- [ ] **Step 2: The pool and the dispatch**

```cpp
// lazily created, owned by the vocab, 8 threads on this box
struct llm_tokenizer_pool {
    std::vector<std::thread> workers;
    // work items are (begin, end, output slot); results are concatenated in order
};
```

Dispatch chunks only when `text.size() >= 4096` and at least two safe splits exist; otherwise tokenize on the calling thread. Results go into per-chunk vectors and are concatenated in chunk order, so ordering never depends on completion order.

### Task 5: AVX2 classification

**Files:**
- Modify: `src/unicode.cpp` (the ASCII classification helper from Task 3)

**Interfaces:**
- Consumes: `classify_ascii` from Task 3 as the scalar fallback.
- Produces: a 32-byte classification that the scanner uses for ASCII runs without per-byte branching.

- [ ] **Step 1: The AVX2 classifier**

Classify 32 bytes at once into the four classes, and let the scanner consume runs. The comparison-based form avoids table lookups:

```cpp
#if defined(__AVX2__)
// returns a mask where each bit is set if the byte is a letter, digit or ASCII space class
static inline void classify_ascii_32(const unsigned char * p, uint32_t * letter, uint32_t * digit, uint32_t * space) {
    const __m256i v = _mm256_loadu_si256((const __m256i *) p);
    const __m256i lower = _mm256_or_si256(v, _mm256_set1_epi8(0x20)); // fold case
    const __m256i a = _mm256_set1_epi8('a');
    const __m256i z = _mm256_set1_epi8('z');
    const __m256i d0 = _mm256_set1_epi8('0');
    const __m256i d9 = _mm256_set1_epi8('9');
    const __m256i is_alpha = _mm256_and_si256(_mm256_cmpgt_epi8(_mm256_add_epi8(lower, _mm256_set1_epi8(1)), a),
                                              _mm256_cmpgt_epi8(_mm256_add_epi8(z, _mm256_set1_epi8(1)), lower));
    const __m256i is_digit = _mm256_and_si256(_mm256_cmpgt_epi8(_mm256_add_epi8(v, _mm256_set1_epi8(1)), d0),
                                              _mm256_cmpgt_epi8(_mm256_add_epi8(d9, _mm256_set1_epi8(1)), v));
    *letter = (uint32_t) _mm256_movemask_epi8(is_alpha);
    *digit  = (uint32_t) _mm256_movemask_epi8(is_digit);
    *space  = (uint32_t) _mm256_movemask_epi8(ascii_space_mask(v));
}
#endif
```

with `ascii_space_mask` built from equality tests against the six whitespace bytes. The comparisons use the `+1` trick to avoid `cmpgt` being strict.

- [ ] **Step 2: Use it for ASCII runs**

In the scanner, when at least 32 bytes remain and the next 32 bytes are all ASCII (checked with the high-bit mask), take the fast path: consume the letter run, digit run or space run directly from the masks, and fall back to the scalar classifier at the run boundary or on any non-ASCII byte.
